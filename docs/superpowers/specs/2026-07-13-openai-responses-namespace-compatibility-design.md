# OpenAI Responses `namespace` 兼容修复设计

## 目标

让使用 sub2api API Key 的 Codex 客户端能够继续调用 OpenAI `/v1/responses`，不再因为上游拒绝 `input[*].namespace` 而收到 502。

## 范围与方案

在 OpenAI Responses 请求完成既有模型、图片工具及 Codex 桥接处理后、向上游发送前，规范化请求体中的 `input`。

- `input` 为数组时：仅删除每一个对象项顶层的 `namespace` 键。
- 不递归删除嵌套对象中的同名字段，避免意外改变用户提供的工具参数或内容。
- `input` 为字符串、对象、缺失或数组中含非对象项时，不作额外改写。
- 仅对实际包含该字段的请求重新序列化，保持无关请求的原始字节和现有行为。

## 错误处理与可观测性

请求体已经在既有逻辑中解码时复用该对象；如果为执行规范化而解码失败，沿用当前的请求错误返回路径。该兼容清理是确定性的本地转换，不新增日志中的请求内容，避免泄漏用户输入。

## 验证

新增聚焦单元测试，覆盖：

1. 多个输入对象中仅含 `namespace` 的项会被正确清理，其他字段保留。
2. 不含 `namespace` 的请求不变。
3. 非数组 `input` 和数组内非对象项不变。

本地运行相关 Go 测试及后端编译。发布后检查容器健康，并观察 Codex `/v1/responses` 请求不再因该参数产生上游 400/客户端 502。
